# Known Limitations & Future Improvements

## Current limitations

- **Synthetic data only.** No real access logs were used or are available;
  all reported metrics reflect performance on data generated by our own
  assumptions about "normal" and "attack" behavior. Real-world distributions
  will differ.
- **Cold-start is heuristic, not learned.** Entities with < 20 events fall
  back to a hand-weighted rule-based score. A production system would want a
  learned prior (e.g. population-level embeddings) instead of fixed weights.
- **Concept drift is not actively handled**, only tolerated implicitly by the
  fact that `insider_drift` events are labeled separately for false-positive
  tuning. There's no retraining trigger or drift-detection statistic
  (e.g. population stability index) in this build.
- **Polling, not streaming.** The dashboard polls `/alerts` every 5 seconds
  to simulate real-time updates. A production deployment would use
  websockets/SSE and a real event stream (Kafka, etc.) instead of ingesting
  batches via REST.
- **SQLite, single-process.** Fine for a hackathon demo; would need
  Postgres/Elasticsearch and a proper message queue for production load.
- **No retraining pipeline.** The model is trained once, offline, and loaded
  at API startup. There's no automated retraining schedule or online
  learning loop.
- **Small feature set.** Deviation features are deliberately simple
  (6 dimensions) for interpretability and beginner-scope training time. A
  richer feature set (e.g. n-gram command sequence embeddings, graph
  features for entity-resource relationships) would likely improve
  detection of subtler attacks like low-and-slow exfiltration, which had
  the weakest recall in our evaluation.

## Future improvements

- Add a drift-detection statistic (e.g. KL divergence between recent and
  historical feature distributions per entity) and trigger periodic
  retraining.
- Replace polling with websockets for genuinely real-time alerting.
- Add a Transformer-based variant and compare against the GRU baseline on
  longer sequences.
- Add graph-based features (entity-resource bipartite graph) specifically to
  improve lateral-movement detection.
- Persist model versions and add a simple A/B comparison view in the
  dashboard.
